# Rust migration: verified incremental phases

## Implemented in this branch

A dependency-free **read-only Rust audit** under rust/audit checks source-module/guidebook byte parity, mandatory AUD-001 through AUD-020, stable rule-ID uniqueness, required sources, generated adapters, and the lock's rule count. This is a useful, independently coded second check. It neither mutates nor deploys anything.

Commands (Rust 1.85.1):

    cargo +1.85.1 test --locked --offline --manifest-path rust/audit/Cargo.toml
    cargo +1.85.1 run --locked --offline --manifest-path rust/audit/Cargo.toml -- check .

## Migration acceptance gates

The **existing Python 3.10+ builder/check/adopt CLI remains authoritative**. Do not remove it. The Rust checker does NOT yet replace Python schema, hashing, credential detection, local-link verification, file enumeration, atomic file writes, or safe adoption.

For later phases, port operations individually with real fixtures. Compare generated bytes/digests to Python, policy parsing, paths-with-spaces, symlink escapes, ignored/tracked files, privacy detection, bad UTF-8, malformed policy, CLI error codes, idempotency, adapter preservation, interrupted writes, Windows/macOS and cross-platform behavior. Keep a per-feature parity matrix and only switch entrypoints after parity, tests and review. User instructions and safety checks must not degrade to satisfy a language preference.

## Evidence and limits

CI should run this Rust executable and its unit tests alongside the original Python suite. No provider-specific behavioral compliance is established. A hash or source-byte match does not prove semantic correctness. This branch was authored in an environment without rustc/cargo, so native compilation requires GitHub Actions verification before merging.

Zero dependencies, no required software subscription. Incremental software TCO: $0 excluding developer time, optional CI usage and local compute/energy.
