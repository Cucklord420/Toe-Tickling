# Historical Python and current Rust CLI coverage

## Reference and scope

The last published Python implementation before the Rust migration is pinned at commit [`0bdc6fed00c35cec4ff3bf756da9d1f9dbb0c3a9`](https://github.com/Cucklord420/Toe-Tickling/commit/0bdc6fed00c35cec4ff3bf756da9d1f9dbb0c3a9). Its `scripts/guidebook.py` selected `ROOT = Path(__file__).resolve().parents[1]`, so invoking that script by path from an unrelated current directory still selected the script's checkout. The revision contains 45 Python test methods in `tests/test_guidebook.py`.

The Rust CLI now defaults to the package manifest directory through Cargo's compile-time `CARGO_MANIFEST_DIR`; `--root PATH` still selects another checkout. The ignored Rust integration test `tests/python_rust_parity.rs` clones the pinned historical commit from local Git history, verifies the CLI source hash, and compares the historical Python and current Rust commands against independent output, checksum, and refusal expectations. It covers help inventory, `build`, `check`, invalid date/version/source traversal, read-only adoption preview, and synthetic adoption apply. The apply regression requires exactly the seven planned managed-file changes and four new parent directories, while preserving every original byte in `AGENTS.md`, `.gitignore`, and `CLAUDE.md`. Its dedicated Ubuntu, Windows, and macOS workflow job pins Python 3.15.2 and runs only these five Rust tests; it does not run or add Python tests. The fixtures canonicalize Unix temporary parents so the security checks do not mistake `/var`'s macOS symlink for a target path. Every CLI call uses an unrelated working directory, and each test checks that it remains empty. Existing tests continue to exercise explicit `--root` selection and adoption paths containing spaces.

## CLI and artifact inventory

The pinned Python CLI accepts top-level and subcommand `-h/--help` and three subcommands: `build` (no options), `check` (no options), and `adopt TARGET [--apply]`. It always uses the checkout containing `scripts/guidebook.py`; it has no `--root` override. `build` generates `GUIDEBOOK.md`, `guidebook-lock.json`, `AGENTS.md`, `prompts/USE_WITH_ANY_MODEL.md`, `prompts/STANDING_MEMORY.md`, `CLAUDE.md`, `GEMINI.md`, `.github/copilot-instructions.md`, and `.cursor/rules/justin-guidebook.mdc`. `check` prints a JSON report and is read-only. `adopt TARGET` prints a read-only plan by default; `--apply` writes the seven planned managed paths while preserving project-owned instruction text and existing adapters.

The current Rust CLI accepts top-level `--help` and `--root PATH`, plus `build`, `check [--audit PATH]`, `render [--check]`, `refresh-manifest`, `new-audit --task TEXT --output ABSOLUTE_PRIVATE_PATH`, and `adopt TARGET [--apply | --recover]`. Its `build` generates `GUIDEBOOK.md`, `RULEBOOK.md`, `guidebook-lock.json`, `prompts/USE_WITH_ANY_MODEL.md`, `prompts/STANDING_MEMORY.md`, `CLAUDE.md`, `GEMINI.md`, `.github/copilot-instructions.md`, and `.cursor/rules/justin-guidebook.mdc`. `check` and `render --check` are read-only. Rust adoption `--apply` is paused on all platforms in the current `main` snapshot. `--recover` remains callable and may mutate an existing journal; its path-race safety is tracked separately by Issue #39 and is not proved by this parity suite. The help inventory and read-only help behavior are covered by `tests/python_rust_parity.rs::cli_help_lists_commands_and_options_without_writes`.

It uses local Git history only, Python isolated/no-bytecode mode, synthetic targets, and a temporary directory. Credential and ambient Git-context variables are removed from child processes.
- The test pins per-artifact SHA-256 goldens for all nine historical Python outputs from that commit and all nine Rust outputs from `main` at `db2146f781e9c088d3694cfb77bd5434ec90839a`. The values are constants in the Rust regression, not hashes derived from the newly generated outputs.
- Four historical symlink test methods use a Windows skip decorator. The new fixture does not rerun the historical Python test suite, so its old Windows skip count is not a new observed run.
- In the Windows authoring shell checked on 11-16-2026, `cargo`, `rustc`, and `rustfmt` were unavailable; `python` resolved only to the Microsoft Store execution alias. No local Rust compile, test, formatting, or Python comparison was run. The pinned CI jobs below provide the observed execution evidence.
- A dedicated locked Rust integration-test job is configured for Ubuntu, Windows, and macOS, each with the pinned Python interpreter. `actions/setup-python` v7.0.0 is pinned to commit `5fda3b95a4ea91299a34e894583c3862153e4b97`. Rust adoption `--apply` remains paused on all platforms until Issue #39's race is closed and that behavior is asserted as the expected safe deviation.

## Intentional migration differences

The approved design accepts these behavioral differences as migration scope, not as byte-for-byte parity:

- The current Rust policy and generated bundle have grown since the Python snapshot. Generated guide/adapters and their digests are expected to differ.
- The Python `check` command printed a JSON report; the Rust `check` command prints human-readable structural-check output. Exact terminal text and error formatting are not golden-compatible.
- Python uses `argparse`'s detailed help text; Rust has a concise hand-written top-level command summary. The fixture checks the command inventories, Python's `adopt --help`, and that help is read-only, not byte-for-byte help text or every subcommand-specific usage error.
- Rust adds `render`, `refresh-manifest`, `new-audit`, and adoption recovery. These commands are additions, not Python parity requirements.
- The source-root behavior is intentionally restored: default commands select the package manifest directory, while `--root PATH` is retained for another checkout.

The root-selection regression is a targeted compatibility repair. The new differential fixture adds independent output/checksum goldens, exit-code and refusal checks, repeat-build stability, synthetic adoption previews, and disposable Python apply/idempotence checks; exact-head CI passed across the configured operating systems at `ae7caa9c0d61569051b09598e5ea5578731a72f3`. The broader 45-scenario mapping still contains the partial and untested cases shown above, and the tested differential set does not prove model behavior or platform-specific mutation safety. Issue #23 stays open until the change is independently reviewed, merged, and verified on `main`.
