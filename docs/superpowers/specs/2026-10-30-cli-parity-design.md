# Rust CLI root compatibility design

**Intent.** Preserve the original guidebook command's repository selection when the Rust CLI is launched from an unrelated current directory.

**Observed behavior.** The pinned Python CLI set its root from `Path(__file__)`, so invoking the script by path always selected the repository that contained it. The Rust CLI currently uses the process current directory unless `--root` is supplied. That makes `cargo run --manifest-path <repo>/Cargo.toml -- check` fail when launched elsewhere, even though the old entrypoint worked.

**Goals.** Default Rust commands to the crate's manifest directory; preserve `--root PATH` as the explicit override; add a Rust integration test that runs the real `build` and `check` commands from an unrelated directory; record historical Python and current Rust evidence alongside intentional migration differences.

**Approaches.** (1) Use Cargo's compile-time `CARGO_MANIFEST_DIR` as the default and retain `--root`; selected because it reproduces the old script-root behavior with the smallest deterministic change. (2) Keep the current-directory default and document the break; rejected because the issue explicitly requires preserving accepted CLI behavior. (3) Search the working directory or executable's ancestors for a repository; rejected because it is ambiguous and does not reproduce the old script's fixed root.

**Constraints and non-goals.** New executable code and tests remain Rust. Do not restore or add Python implementation or test files. Keep the newer Rust commands, security rules, and generated policy. Exact generated bytes and terminal text intentionally differ because the Rust policy has expanded; record those differences instead of claiming byte-for-byte parity. `--root` remains the way to target another checkout.

**Verification.** The new integration test must fail against the current-directory default and pass after the change. Run the historical Python suite from its pinned commit and compare the scenario coverage with current Rust tests. Run the full locked Rust validation and Linux/Windows CI on the final head. A locally installed toolchain is Rust 1.99.1, edition 2024; the local Windows linker is unavailable, so GitHub CI supplies compilation and test evidence.
